Schwachstellensuche mit Erlaubnis

Klaus
hackt.

Du gibst ihm ein Ziel, eine Erlaubnis und zwei Stunden. Er findet die Lücken, bevor es jemand anderes tut, und wird mit jedem Fund besser.

Nur mit Erlaubnis. Ohne Scope-Datei startet nichts. Nur im Scope. Jede Anfrage wird einzeln geprüft. Nie schneller als erlaubt. Standard 2 Anfragen pro Sekunde.
In 5 Minuten starten Quellcode ansehen
Was er prüft

Drei Wege hinein. Dieselben, die Angreifer nehmen.

Mit Quellcode liest er den Code. Ohne Quellcode prüft er nur das, was jeder Besucher auch sieht. Mit Testkonten prüft er, ob jeder nur seine eigenen Daten bekommt.

White-Box · mit Quellcode

Der Code wird gelesen

  • API-Keys, Passwörter und private Schlüssel im Code
  • SQL- und Befehls-Injection, XSS, SSRF, unsichere Deserialisierung
  • Bibliotheken mit bekannten Lücken (OSV-Datenbank)
  • Claude liest jede geänderte Datei und sucht Logikfehler

  • CORS, Cookies, Sicherheits-Header, Clickjacking
  • Fehlerseiten mit Stacktrace, reflektiertes XSS
  • Geheimnisse und API-Endpunkte im ausgelieferten JavaScript

Die Scope-Datei

Erst die Erlaubnis, dann der erste Request.

Alles, was ein Bug-Bounty-Programm vorgibt, steht in einer Datei. KlausHackt liest sie vor jedem Lauf und hält sich bei jeder einzelnen Anfrage daran.

scopes/meine-app.tomlTOML
name = "meine-app"gueltig_bis = "2027-03-31" [erlaubnis]nachweis = "../nachweise/freigabe.pdf"bestaetigt = true [ziele]urls = ["https://staging.meine-app.de/"]ausgeschlossen = ["https://staging.meine-app.de/admin"] [regeln]anfragen_pro_sekunde = 2erlaubte_methoden = ["GET", "HEAD", "OPTIONS"] [programm.belohnungen]kritisch = "1.000–5.000 €" [[testkonten]]name = "nutzer_a"header = { Cookie = "session=…" }

  1. Läuft ab

    Jeder Scope hat ein Ablaufdatum. Danach verweigert KlausHackt den Start.

  2. Erlaubnis ist Pflicht

    Nachweis als Datei oder Link zum Programm, plus deine ausdrückliche Bestätigung.

  3. Ausgeschlossen heißt ausgeschlossen

    Host, Port und Pfad werden bei jeder Anfrage geprüft. Weiterleitungen aus dem Scope heraus folgt er nicht.

  4. Das Tempo des Programms

    Viele Programme erlauben 2 bis 10 Anfragen pro Sekunde. KlausHackt bleibt darunter, bremst bei 429 von selbst ab und geht nie über 10.

  5. Testkonten statt Kunden

    Eingeloggte Bereiche werden nur mit Konten geprüft, die im Scope stehen.

Schweregrade

Von „gut zu wissen“ bis „sofort handeln“.

Jeder Fund kommt mit Ort, Beleg, Erklärung in normalem Deutsch und einer konkreten Behebung. Steht eine Belohnungstabelle im Scope, rechnet der Bericht sie gleich mit ein.

Der Lern-Loop

Jeder echte Fund wird zur Suchregel für den nächsten.

Das Modell selbst lernt nicht dazu. Das Gedächtnis um es herum schon: Was du bestätigst, sucht er überall. Was du als Fehlalarm markierst, meldet er nie wieder.

Bestätigter Fund · server.py:75 
zeile = db.execute(f"SELECT name FROM produkte WHERE id = '{id}'")
↓ wird zur Regel gelernt-330d9535 
\w+\s*=\s*\w+\.execute\(\w+["'`][^"'`]*["'`]\)
↓ findet beim nächsten Lauf auch 
res = conn.execute(f"DELETE FROM log WHERE tag = '{t}'")

Dazu kommen: Techniken, die oft Echtes finden, laufen zuerst. Unveränderte Dateien werden nicht doppelt von Claude gelesen. Verschwundene Funde gelten als behoben, und kommt einer zurück, steht WIEDER DA daneben.

Leitplanken

Was KlausHackt nie macht.

Keine Massenscans

Keine Wortlisten, kein Durchprobieren. Eine kleine feste Liste typischer Lecks, sonst nur Seiten, die verlinkt sind.

max. 60 Seiten · Budget pro Lauf

Keine Schäden

Nur lesende Anfragen. Keine Formulare absenden, nichts löschen, keine Last erzeugen. Bei wiederholten Serverfehlern bricht er ab.

GET · HEAD · OPTIONS

Keine echten Nutzerdaten

Geheimnisse werden im Bericht maskiert. Zugriffstests laufen nur mit Testkonten.

Nichts ohne dich
